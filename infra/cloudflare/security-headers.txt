WHY securityheaders.com shows F on nightingale-security.com
============================================================

GitHub Pages (origin) IGNORES _headers for security policies.
security.txt is already live from Pages. Response security headers
are NOT — they only appear after the Cloudflare Worker is on the
request path (or Transform Rules are created in the CF dashboard).

Code is ready in:
  - infra/cloudflare/agent-discovery.js  (sets all graded headers + strips ACAO *)
  - infra/cloudflare/wrangler.toml       (routes for apex + www)
  - _headers                            (documentation / future CF Pages)

Deploy NOW (local — needs browser login):
  cd infra/cloudflare
  ./deploy.sh

Or CI: add repo secrets CLOUDFLARE_API_TOKEN + CLOUDFLARE_ACCOUNT_ID,
then push / run workflow "Deploy Cloudflare Worker".

Fallback (no Worker): Cloudflare Dashboard → Rules → Transform Rules
→ Modify Response Header — copy values from agent-discovery.js
applySecurityHeaders() / MARKETING_CSP. Also remove
Access-Control-Allow-Origin.

Also enable: SSL/TLS → Edge Certificates → Always Use HTTPS + HSTS.

Do NOT attach this Worker to dashboard.nightingale-security.com.

Verify:
  curl -sI https://nightingale-security.com/ | grep -iE 'strict-transport|content-security|x-frame|x-content|referrer|permissions|access-control'
  https://securityheaders.com/?q=https%3A%2F%2Fnightingale-security.com%2F&followRedirects=on
